VF2 Offline Patcher Transparency Log
====================================

Purpose
-------
This document describes the offline VF2 patcher design used by the B103 patcher
refresh. Each exported patcher bundle also generates its own Transparency
Log.txt with exact manifest counts, launcher metadata, paths, and changelog
details for that bundle.

What the patcher does
---------------------
- Verifies the user-selected vanilla Virtual Families 2 executable before
  applying patches.
- Reads patch records and asset records from manifest.json.
- Applies only records whose required settings are enabled.
- Creates backups before writing changed files.
- Writes machine-readable success/failure logs.
- Streams per-record validation/apply progress to the CLI and GUI.
- Creates a separate, clearly labeled modded output folder by default.
- Names the modded executable clearly so it is not confused with vanilla.
- Provides restore support for backups created by the patcher.

What the patcher does not do
----------------------------
- Does not inject code into a running game.
- Does not edit process memory.
- Does not use obfuscation or packers.
- Does not require admin-only install locations.
- Does not alter original saves unless the user manually copies saves.

Payload folder
--------------
The payload/ folder is the patch bundle's local stash of files that may be
copied into the separate modded output folder. It is not applied blindly. Each
file must be referenced by an asset_patches record in manifest.json, and the
patcher verifies the payload file's source_sha256 before copying it.

Payload contents usually mirror game-folder paths:
- payload/Virtual Families 2 - Modded B###.exe: the current full modded EXE
  payload while native byte/table records are still being extracted.
- payload/Assets/: furniture fmap files and other runtime asset metadata.
- payload/Images/: generated sprites, copied runtime images, Outfit icons,
  villager sheets, TV animation strips, furniture art, and UI art.
- payload/Sounds/: runtime sound files when exporting a full beta-folder
  patcher.
- payload/OptionalVisualMods/: optional visual-mod source files such as custom
  map images, transparent UI bars/tabs, and Invisible Furniture visible or
  transparent graphics.
- payload/Original Virtual Families 2 Assets/: preserved reference/source
  assets needed to reproduce the cleaned beta-folder structure.
- payload/*.dll, ldw.ini, wc.dat, icon.bmp, and similar root files: runtime
  support files included by full-folder smoke-test bundles.

Unchecked patch settings should leave their payload files unused and, for
feature-specific payloads, absent from a fresh modded output folder. Optional
visual source folders and Invisible Furniture visible/transparent graphics are
assigned to their own default-off settings so unchecking those settings omits
their records.

Important files
---------------
- work/offline_vf2_patcher.py: CLI patcher, manifest validation, backups,
  restore, per-record progress, and JSON patch logs.
- work/offline_vf2_patcher_gui.py: Tkinter GUI for choosing the vanilla game,
  toggling settings, applying patches, restoring backups, and showing the
  completion summary.
- work/export_offline_patch_bundle.py: source-side exporter that creates
  manifest.json, payload files, runner scripts, launcher metadata, and generated
  Transparency Log.txt.
- work/patch_mobile_furniture_pack.py: current build generator that produces
  the modded beta folder used as patcher payload input while native byte/table
  records are still being extracted.

Current B103 behavior
---------------------
- The manifest declares a separate output folder named VF2-B103-Modded.
- The core executable record validates Virtual Families 2.exe but writes the
  patched file as Virtual Families 2 - Modded B103.exe.
- Optional visual settings default off.
- Invisible Furniture visible graphics and transparent graphics are separate
  default-off settings.
- Settings Evict, mobile furniture behaviors, Holiday Ornaments, and Island
  Events remain default off experimental settings.
- The GUI completion popup lists enabled patches, altered files, the modded game
  folder, and the modded save folder.
- Modded saves are expected under Documents/LDW/(name of modded Virtual
  Families 2 exe).
- Existing vanilla saves can be copied manually into the modded save folder.
  Original saves remain untouched.

Unchecking patches
------------------
Unchecked asset and file settings are reverted by omission when the patcher is
run into a fresh modded output folder. Their records are not copied, replaced,
or created. This applies to optional visual source folders, active transparent
UI swaps, custom map images, Invisible Furniture visible graphics, and
transparent Invisible Furniture swaps.

Known limitation
----------------
The current full beta-folder bundle still uses a verified full modded EXE
payload for native/game-code changes. Those native changes cannot be completely
split by checkbox until they are converted into separate byte/table patch
records with their own setting requirements. This is the next transparency and
antivirus-trust milestone.
