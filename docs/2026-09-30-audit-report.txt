DEFECTS FOUND AND FIXED (with the PR that fixes each)
------------------------------------------------------
Crash
 #384  ISSUE #378 ROOT CAUSE. Dropping a villager on these could crash once
       the store's Pets page had been shown:
       - Invisible Patio Table
       - Invisible Picnic Table
       - Invisible Lounger
       - Invisible Spa Lounger
       - visible Spa Lounger
       Cause:
       - Their placement maps carried mobile-only hotspot numbers
         (0x6B-0x6D).
       - The PC drop handler indexes its table without a bound. It read a
         pet item number (0x240-0x244) and executed it.
       Reproduced LIVE on B196 under a debugger (access violation executing
       0x245). After the fix:
       - Footprints are unchanged: the same cells are occupied as in B196.
         The maps differ only where a mobile hotspot number was removed
         (a hotspot-only cell keeps an inert occupancy bit instead).
       - Unticking Mobile Furniture Behaviors no longer restores the raw
         maps.

Villagers
 #405  Careers could not be maxed. Behavior Patches reset the career
       activities' weights on every load, which erased praise training; the
       base game uses that training to drive career progress while the game
       is closed. Career rows now stay exactly as in the base game; the label
       variations are kept.
 #385  The computer-drop coin flip read the villager's AGE (+0x6A54)
       instead of the current behaviour (+0x1BBA0). It almost never fired on
       a computer, and instead fired on any drop of a villager aged exactly
       4.5.
 #395  The hammock was never chosen in Cloudy weather: a stock Sunny-only
       field had been left in place.
 #403  Fireplace, foosball, pinball, slots, pachinko, the kids table, the
       easel, the playhouse and couch sitting were offered in houses without
       that furniture. They now require it.
 #398  Praise/scold training of hammock, playhouse, snow, gym and yoga was
       reset on every decision.
 #397  The stock Treadmill could show Exercise Bike captions. One 40-byte
       label was truncated.
 #394  Picnic and Patio tables now match the VF2 mobile game (taken from its
       code):
       - the correct refusal text;
       - props on every table for 300 s;
       - several preparers at once;
       - every preparation activates the props.

Base-game (vanilla) bugs -- the new "Fix Vanilla Game Bugs" setting
 #411  Title Start Over did exactly what Continue does: both buttons ran the
       same code. Now:
       - It asks "Are you sure you want to restart the current game?"
       - OK starts a new village for the same player.
       - Cancel changes nothing.
       - It uses the steps the game's own new-player dialogs take (Init,
         keep the name, save), never the developer-dead
         RestartCurrentGame routine.
 #412  NEW SETTING "Fix Vanilla Game Bugs" (Main, on by default), as you
       asked.
       - It is one byte (.vf2bugs) in the patched executable, the same kind
         of switch as Allow Older Pregnancies, so it adds no extra builds.
       - Unticked, every site runs the original game's instructions.
       - Start Over (#411) now lives under it.
       It also fixes these stock bugs:
       - Settings > Pause Game: Yes while already paused stored the pause
         twice (2008). One Space press then left the game paused (1009) and
         a second press was needed. The second +999 is now skipped.
       - An invisible Change Player click spot sat on the title screen at
         the Manage Games button's position before the game moves it.
         - That rect is now emptied.
         - Its code is left in place, per your no-dead-code-removal
           instruction.
       - The title screen went stale:
         - Play/Continue was chosen once, at load.
         - The player name appeared only after a dialog closed.
         - Manage Games vanished for the session after the last player was
           deleted.
         - Cancelling the name prompt left the deleted player's name and
           "Continue" on screen. Live testing found this last case, and it
           is fixed too.
         The fix: the game's own UpdateShowPlayer now re-applies the label
         and re-adds Manage Games. It runs whenever the title is shown and
         when the name prompt is cancelled.
       - Codex flagged that two older validator scripts did not know the new
         section. That was fixed, and Codex then approved.

Invisible furniture (you asked that every fix also apply to it)
 #414  I searched the base game for the stock item number of all 33
       invisible items. Almost everything already treated the invisible
       copies like the stock ones:
       - The furniture a villager chooses on its own is recognised by the
         kind of object it is, which the invisible copies share.
       - The click table and every route this patcher adds list both items.
       - Every fix from this audit applies to them.
       Seven places in the base game asked for one exact stock item, so the
       invisible copy did not count: six item checks (redirected to a new
       "stock or invisible" helper) and the goal switch (which now
       translates an invisible pool or MP3 player to its stock item first):
       - Goals: "Staying cool in the pool" (Invisible Kiddie or Full-Size
         Pool) and "Let's dance" (Invisible MP3 Player). Both are CONFIRMED
         LIVE: each completed in a village whose only pool, or only music
         player, was the invisible one.
       - Kiddie pool play: children never chose to play in an Invisible
         Kiddie Pool. The two activities required the stock pool by item
         number.
       - Happiness: the "likes" bonus came only from the stock MP3 player,
         pools and hammock.
       - Clicking the Invisible MP3 Player was silent unless a stock one was
         also placed.
       All seven now accept the invisible copy, in every executable.
       - The hammock had no item check on how villagers choose it.
       - "Filling in a hole" uses the number 0x1E5 as a yard position, not
         as an item, so it needed nothing.
       Codex approved; 8 deliberate breakages of the fix were all caught by a
       test.
